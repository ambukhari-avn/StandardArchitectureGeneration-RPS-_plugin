# Decisions

Choices made so far, with the reason. Change one only by editing this file and saying why.

| # | Decision | Reason |
|---|---|---|
| D1 | Scripts the plugin runs use only the Python standard library. Dev and test tooling may use more. | The plugin may run where `pip install` and network access are unavailable. |
| D2 | A `.vsdx` is written directly as an OPC zip of XML. The package skeleton (styles, theme, windows, content types) is copied from an existing Visio-made file; only page contents, page size and core properties are replaced. | A hand-written package from ChatGPT would not open in Visio: stray root part, no styles or theme, colours without `#`, `<Text>` before `<Geometry>`, a page sheet in the wrong place. A skeleton from a real Visio file avoids that class of fault. **Not yet confirmed in real Visio.** |
| D3 | The language model (Claude originally, now ChatGPT, see D26) only produces a structured spec (what goes in the diagram). Fixed code validates it, lays it out and writes the file. | Models are unreliable at spelling and positioning; that is what went wrong in the ChatGPT images. |
| D4 | Output is always A3 landscape (16.5354 x 11.6929 in) and always one page. The writer refuses any other size. | Project requirement. |
| D5 | The footer is fixed: title block, notes, legend, logo. Its field values come from a form the user fills in. Size is always printed as A3. Missing fields stop the run (or print `TBC` if explicitly allowed). | Every diagram carries the same footer; nothing is guessed. |
| D6 | Cable colour, dash and label come from a cable type table, never from the spec. Placeholder values (Ethernet blue, fibre green, as on the Maaden and KSU drawings) are used until the client's standard arrives. | The legend and the drawn lines must always agree. |
| D7 | Legibility floor is 6 pt (configurable). Content that cannot fit above it fails with a report; it is never shrunk further or dropped. | Silent shrinking or dropping produces drawings that look right and are wrong. |
| D8 | A component is drawn as a picture only if the dataset has a picture for it. Everything else is a rectangle with its name inside. | Client decision. |
| D9 | The dataset workbook is used as the client supplied it. The client states it is verified. | Client decision. Anything odd found while using it goes in `open-questions.md`, not into silent edits. |
| D10 | Every diagram follows the Purdue model. Vertical bands come from a Purdue level, and the mapping from dataset layer names to levels is a table, not hard-coded. | Client decision. The mapping itself is still to be confirmed (see open question Q3). |
| D11 | Collapsing identical items into one icon with a count is off by default and configurable. | The client has not approved it. |
| D12 | The ChatGPT images are negative examples only ("how AI diagrams look"). Corrected versions are not needed. | Client decision. |
| D13 | Generated files go to `Downloads\out`. | User decision. |
| D14 | Hooks enforce the checks (validate before writing, check after writing, protect the dataset), so they cannot be skipped by forgetting an instruction. | A rule in a text file can be missed; a hook cannot. **Superseded (D26, D40): ChatGPT has no hooks; every check lives in the scripts.** |
| D15 | Whether each picture is stored once in the file or pasted per use is decided with file-size evidence in Phase 5. | The 87 MB Murtiba `.vsdx` (154 media files, 284 embedded objects) shows what per-use pasting costs. |
| D16 | The spike code (`scripts/spike/`) is reference only. It hard-codes local paths and one project's layout and is not part of the runtime. | It proved the BOQ-to-file path; the real modules replace it phase by phase. **Superseded (D40): the spike code was removed.** |
| D17 | **Pictures from the dataset workbook.** A picture belongs to the row it visually sits in (measured with the sheet's real row heights, since the pictures are taller than their anchors suggest). Where several pictures are stacked in one row, the top-most one is used, because that is the one Excel shows; the others are listed in `docs/dataset-import-report.md`, not exported. | The workbook's own note says pictures are "anchored to their component rows", but five anchors start on a neighbouring row and three rows have stacked pictures. |
| D18 | **Items without a dataset component are drawn as a rectangle with the BOQ wording inside, and listed in the diagram's Notes.** *Provisional: your rule "others will have box representations only", applied to BOQ headings that match nothing. Confirm that the text comes from the BOQ.* | Of Korangi's 17 BOQ category headings only 1 matches a dataset component, so "stop and ask" for each one would make the tool unusable. **Superseded (D40): the wording is now the user's words from the prompt, not a BOQ line.** |
| D19 | **Matching is exact, never fuzzy.** A BOQ line matches only by a confirmed alias, an exact order-number token (6+ characters mixing letters and digits, taken from outside the brackets of the dataset's part number), or an exact title with brackets included. BOQ category headings fold plurals ("Flame Detectors" = "Flame detector"). Look-alikes are suggestions in a report only. | A looser rule matched "Capacitive Level Switch" to "Level switch (vibrating fork)" and "M580 kit" to a hot-standby pair, which would put a wrong label on a diagram. **Superseded (D40): matching is now by the title or order number in the user's quote (`matching.py`); there is no alias list.** |
| D20 | A picture used many times is stored once in the file; every placement points at it. | Tested: six placements of two pictures produce two media parts. This answers D15 in favour of "store once". Murtiba's 87 MB file shows the alternative. |
| D21 | Aliases (BOQ wording to component) are added to `data/aliases.json` only after a person confirms them. The file starts empty. | An alias is a judgement, for example whether "Workstation" is the "Client / operator workstation". **Superseded (D40): no alias list; the model asks the user instead.** |
| D22 | **Cable colours are the client's standard** (`System Architecture Drawing Instructions.docx`, section 1): Ethernet blue (copper), Fibre red, Modbus green, BACnet purple, Hardwired black. Field-to-PLC control signals are always hardwired, so the two black rows are one type. The document gives no dash style, so every type is solid. | Client decision; the field-PLC answer is from the user. Fibre was green on every sample drawing, so existing drawings and the new standard differ. |
| D23 | **Instruments (field devices) are always boxes, even where the dataset has a picture** (for example the emergency stop push button). Third-party connectivity and the DMZ (Level 3.5) are also boxes. | Client instruction (section 2). |
| D24 | **The DMZ (Level 3.5) is drawn only when the user's prompt asks for it,** as boxes. What goes in it (firewalls, switches, cybersecurity servers and so on) comes from the prompt; the WAVE example shows the style. | User decision. |
| D25 | **A server is a VM when its BOQ line says so.** A VM is drawn as a dashed "Virtual Environment" box with a note number; what runs inside it is listed as boxes in a side panel for that note (WAVE example). | User decision, instruction document and example. |
| D26 | **Target platform changed from Claude to ChatGPT (user, 2026-10-20).** Everything in `scripts/` and `data/` is plain Python and data and is unaffected. The Claude-specific packaging (`.claude-plugin/`, `skills/arch/SKILL.md`, the planned hooks, and the instruction wording that says "Claude") is superseded and will be replaced once the ChatGPT form is chosen (open question Q40). | User decision. The earlier D14 (hooks enforce the checks) no longer holds: ChatGPT has no hooks, so every check must live inside the scripts. |
| D27 | **A BOQ is read by `boq_parser.py`.** Columns are found by header text; only Sr, Description, Model, Make, Unit and Qty are read (never prices). Headings come from the Sr column and from description-only rows; a chain of two or more headings sets the parents, and a new heading of the same kind replaces its sibling. Every row with content ends up in lines, headings, zero-quantity, no-quantity or ignored, and the parser reports that the two counts match. | Tested on all five BOQs (18 sheets): nothing dropped. **Superseded (D40): the BOQ reader was removed.** |
| D28 | **BOQ lines are classified by ordered rules in `data/boq_rules.json`** into device, component, service, software, cable, material, documentation or spares. Description rules look only at the first 70 characters. A line no rule matches is a device *by default* and is reported as such. The rules are provisional (derived from the approved drawings, not from a client rule list). | Long spec text in descriptions made a PC look like a warranty and a GPS clock like a module; matching the headline fixed that. **Superseded (D40): the BOQ classification rules were removed.** |
| D29 | **Quantities become drawn items through `quantity.py`.** Mode `instances` (default) draws one numbered item per unit and refuses more than 12; `count` draws one item labelled "x N"; `type` draws one item with no count. Metres and hours are never items; fractions are rounded up with a note. | Collapsing is off by default (D11) and is never done silently. **Still holds, minus the BOQ units (D40).** |
| D30 | **Images come only from the dataset workbook.** The only pictures the plugin may draw are those embedded in the component workbook for a listed component; everything else is a box. The one other image in the repo is the Avanceon logo the user supplied for the footer. The sample architectures (Maaden, KSU, Kemari, Korangi, Murtiba, WAVE and the rest) are used only to learn structure, grouping and connections, never for their pictures. `tests/test_image_policy.py` fails if any other image appears. | User instruction (2026-10-20). |
| D31 | **The spec is the contract between the model and the drawing code** (`data/spec_schema.json`, checked by `scripts/spec.py`). Every device cites BOQ rows or quotes the prompt; every label traces to the dataset, the cited rows or the prompt; every quantity equals the BOQ; every BOQ device line is drawn or listed in `omitted` with a reason; every connection says whether the prompt stated it or it is assumed. Nothing is drawn from a spec that fails. | The model must not be able to invent a device, label, quantity or link. **Revised (D40): devices quote the user's words, not BOQ rows.** |
| D32 | **A device may name a dataset component only when the cited text matches it exactly** (confirmed alias, order number, title or heading). Otherwise it is a box with the BOQ wording (D18). | A plausible-looking component chosen by judgement is a guess; aliases need a person (D21). **Revised (D40): a component is named by the title or order number in the quote, with the brand if the title is shared.** |
| D33 | **Connection rules in the validator** (`data/spec_rules.json`): levels must be the same or adjacent; a level 0 to level 1 link must be hardwired (client); anything into or out of the DMZ needs a firewall at one end; a DMZ exists only when the prompt asks (D24). | Purdue model for all diagrams (D10); the cable rule is the client's. |
| D34 | **The spec step is model-neutral.** The input pack (`scripts/spec_input.py`) is everything the model may use; the validator is the gate. The step is tried by hand in ChatGPT before any packaging (`docs/chatgpt-trial.md`). | Platform is ChatGPT (D26); packaging form not chosen (Q40). **Superseded (D40): there is no BOQ input pack; the model works from the prompt and the dataset.** |
| D35 | **Connection conventions** are written down from the sample drawings (`docs/connection-conventions.md`) as observations, not client rules. Any link the model adds from them is `assumed` and appears in the diagram's notes. | The BOQs never state connections. |
| D36 | **Layout is by Purdue band, never by the model.** One band per level present, highest at the top, with a level-name strip at the left. Items are placed in centred rows; devices are ordered by where their connected neighbours sit. The item size steps down (1.3 to 0.70) until everything fits one A3 page above the footer; if it still does not fit the build stops and says to use `count` or `type` mode. Fonts never go below 6 pt. | A3 only (D3); no silent collapsing (D11). |
| D37 | **Connections are drawn exactly as the spec lists them**, square-routed through the gap between bands in the cable's colour, one lane each. In `instances` mode each unit of the larger side meets the nearest unit of the smaller side. A route that cannot avoid another item is kept and reported as a warning, never hidden. Links the spec does not list are not drawn (the user can state them in the prompt). | The BOQ never states links (D35); user: unlisted items stay unlinked. |
| D38 | **Footer notes on the drawing are short and generated** (pictures-only-from-dataset, N assumed connections, x N, dashed = VM). The model's longer `notes` and the validator's warnings go to the build report, not onto the page. VM contents go in a side panel; a ring is drawn as a loop in its cable colour around its members. | The notes cell is small (4.7 x 0.84 in). |
| D39 | **The dataset workbook holds two kinds of picture, and both are imported.** Modern pictures (27, PNG) and old-style pictures (VML, 17 shapes using 14 vector `.emf` symbols: workstations, firewall, servers, UPS, printer, switch and others). The first import read only the PNGs and so missed 14 symbols; fixed. `.emf` is rendered to PNG at import time (Pillow, Windows) with the white background made transparent; the runtime still needs only the standard library. Components with a picture: 23 -> 37. Row 37 (Industrial switch) now shows the Cisco switch symbol instead of the limit-switch picture stacked under it. | User pointed out the workstation symbol was not used. |
| D40 | **The user's prompt is the only project input; there is no BOQ (user, 2026-10-21).** Engineers write one prompt and the model asks questions until nothing is unclear. Every device quotes the user's words; a dataset component is named only when the quote names it (title or order number, plus brand when the title is shared, else the model asks); everything else is a box with the user's wording. Removed: the BOQ parser, classifier, report tools, the BOQ input pack, the alias list, the spike code and the Claude packaging (moved out of the repository, not deleted). `.claude-plugin/` is now `chatgpt-plugin/`, which holds the model's instructions. | User decision. |
