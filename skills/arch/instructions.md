# Instructions for /arch

**PROVISIONAL.** These rules come from the project brief and `docs/decisions.md`. They will be replaced or extended by the client's instruction file (open question Q1 in `docs/open-questions.md`).

## Do
- Draw only what the scripts draw. You produce a spec; code validates it, lays it out and writes the `.vsdx`.
- Use labels exactly as they appear in the component dataset. Never type a device label by hand.
- Use a picture only for a dataset component that has one; every other item is a rectangle with its name inside.
- Put every diagram on one A3 landscape page, with the footer filled from the form.
- Take cable colour, dash and label from the cable type table.
- Follow the Purdue model: bands come from the Purdue level of each component.
- Mark any connection, grouping or quantity that was assumed (not stated in the BOQ) in the diagram's Notes.
- Report anything dropped, unmatched or unfitted. Stop and ask when an item is unknown or ambiguous.

## Don't
- Don't position, size or colour shapes yourself.
- Don't invent part numbers, labels, dataset entries, connections or Purdue mappings.
- Don't shrink text below 6 pt or drop an item to make it fit.
- Don't collapse identical items into one icon with a count unless that option is switched on.
- Don't silently correct or ignore a BOQ line; list it.
- Don't fill missing footer fields yourself.
